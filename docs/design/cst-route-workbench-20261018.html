DESIGN RESEARCH / 2026.10.18

专门为“选节点”长出来的界面。

CST 的核心不是展示很多检测结果，而是让人从多个机场里，快速缩小候选，再知道凭什么选它、哪里仍不确定。

为什么当前界面越来越挤

源码核对：QualityMetrics.vue 在服务视图把“每个服务 ID 的最新结果”全部展开；HomeView 没有将所选显示服务传给这一列表。因此上方显示 3 项，右侧却铺开全部历史服务。缺的不是再多一个卡片，而是“列表看摘要、档案看依据、历史看过程”的层次。

横向看什么，借什么

参考可借鉴CST 自己要解决的事
Little Snitch层级列表 / 当前对象检查器节点证据不是连接清单；不把地图当主角。
Proxyman筛选、固定、原始响应下钻范围、比较与历史各有位置；不变成抓包工具。
Surge策略层级与测试条件明确这里只评估节点，不新增自动选路。
Cloudflare AIM / FAST多个质量维度 / 渐进披露缺负载延迟、丢包等必要输入时，不造综合体验分。
异环“拍卖图录”结构来自真实任务和对象借定制方法，CST 使用线路、标尺和出口档案，不照搬拍卖纸张与价签。

两个方向，推荐这一套

A · 线路工作台（本预览）

紧凑节点登记表 + 点选档案 + 勾选对照。节点名称旁就能看到出口类型和带来源的风险参考。六站分布、下载条件和服务结论在固定列里，日常挑选更快。

B · 节点对照册

以条件组为索引、每次测量为一页，适合长期分析与导出；但跨机场快速筛选需要更多翻页。保留这种细读方式给历史和对比，不作为首页。

纵向：从导入到实际选中

机场与账户 → 缩小节点范围 → 看最新同条件证据 → 对比 2～3 个 → 检测明确范围 → 结果自动刷新 → 原始历史 / 导出。 展开节点、循环机场、切换账户都不偷偷改变检测勾选范围。新结果更新数值，冻结排序仍由用户明确刷新。

IP 信誉接谁，怎么接

来源目前核实建议
IPOK已接入；指定 IP API、来源时间、额度、降级缓存有文档。优先复用。默认主动检测加入，不随页面加载或全量后台触发。保留来源回链。
Ping0现有代码和已保存结果有 IP / ASN / IDC / 风险原值；本轮未核实完整公开 SLA 或额度。保留已有结果作独立参考，不据此承诺稳定 API 或低风险。
IPPure官方公开调用方出口 API，明确测试阶段；既有规则有挑战失败。保留可选与旧结果，不作为唯一默认。IPv6 无风险分不补造。
proxycheck.io官方 API、未注册 100 次/日；版本和置信度需各自处理。备选独立来源；IPOK 已聚合该源，不默认再重复查一遍。
ipapi.is匿名 30 次/日且只给归属地等精简字段；完整代理/滥用标记需要 key。有自备 key 时才考虑风险补充，不把缺字段当“干净”。
Net.Coffee / IPLark本轮未核实稳定公开 API。外部查询入口；浏览器网络可能不是被测节点。不上脆弱爬虫。

IPOK 文档给出指定 IP 15 次 / UTC 日额度与上游降级；现有本地预算继续保留。共享出口可以复用查询，但每个节点的出口仍要有自己的观察。厂商分数不平均，不反算“纯净率”。其评分方法在无数值来源时也可能给基础分，因此必须同时显示实际证据覆盖，不能单凭低分说“低风险”。

项目自己的视觉语言

线路折线标志 / 刻度与分布 / 固定测量列 / 出口档案 / 轮次采样条。 海青色用于当前选择和连接证据；琥珀色用于条件不足或挑战；砖红用于明确拒绝。文字说明始终存在，不能只靠颜色。浅色与深色共用结构，数字等宽，节点身份优先。首页不用大地图、大评分圆盘或满屏彩色标签。

怎么落到已有代码

先整理 QualityMetrics 和 HomeView： 修正 3 项显示与全部服务历史混杂，提取节点旁出口摘要，接现有最新结果投影。复用 nodeQuality、sharedResults、测量轮次、历史 hover / 固定、分页缓存与冻结排序。再实现点选档案与对比的同一套字段，最后统一订阅、历史、设置和备份外观。底层检测方法、身份和 SQLite 历史不重做。

KKTV 结束营运规则从日常选择 / 摘要隐藏，旧历史保持可查。默认 IP 方案的真实请求仍须走所选节点并遵守现有预算，物理绑定已核验与实际未被 TUN 转发分别表达。
