# 服务连接与失败阶段（2026-10-19）

服务检测使用所选节点的独立客户端。默认客户端支持标准 HTTP/2 ALPN 协商，并在目标不支持时使用 HTTP/1.1；继续使用原节点拨号、证书验证、物理出口、总时限和连接预算。不添加失败重试；下载、延迟检测和调用方提供的共享客户端不改协议策略。

连接错误跟随发生错误的那一条请求记录阶段，避免复合检测中较早的成功请求掩盖后续 TLS 失败。`Details.request_failure_phase` 的可观测值：

| 值 | 含义 |
| --- | --- |
| `proxy_connect` | 所选节点代理拨号失败 |
| `tls_handshake` | TLS 握手失败，或取消/超时时仍在握手 |
| `request_write` | HTTP 请求写入失败 |
| `response_headers` | 请求已写入，取得响应头之前失败 |
| `response_read` | 已有响应，读取正文时失败 |

没有对应事件就不猜阶段。累计握手、写请求、耗时等字段仍是整次检测的统计，不能据此推断某一条请求成功或失败。普通传输错误的 `FailurePhase` 使用具体阶段；取消仍是 `cancelled`，超时仍是 `timeout`，具体阶段另存在 Details。`timeout_origin` 区分 `checker_deadline` 和 `transport`。

原始 HTTP 状态、实际读取字节、底层取消/超时错误和脱敏规则保留，应用层照常将这些字段保存到历史；旧记录不重写。HTTP 403 验证页属于已连通但被网页验证阻挡，不因此宣称节点连接失败或服务业务可用。

验证覆盖复合请求后续 TLS 失败、代理建连失败、正文中断、超时/取消、HTTP/2 与 HTTP/1.1 回退；本地服务器验证也核对原节点拨号路径和实际连接次数。协议兼容改进不代表已证明某个历史超时的原因。
