# 服务连接与失败阶段（2026-10-19）

服务检测使用所选节点的独立客户端。默认客户端支持标准 HTTP/2 ALPN 协商，并在目标不支持时使用 HTTP/1.1；继续使用原节点拨号、证书验证、物理出口、总时限和连接预算。不添加失败重试；下载、延迟检测和调用方提供的共享客户端不改协议策略。

连接错误跟随发生错误的那一条请求记录阶段，避免复合检测中较早的成功请求掩盖后续 TLS 失败。`Details.request_failure_phase` 的可观测值：

| 值 | 含义 |
| --- | --- |
| `proxy_connect` | 所选节点代理拨号失败 |
| `tls_handshake` | TLS 握手失败，或取消/超时时仍在握手 |
| `request_write` | HTTP 请求写入失败 |
| `response_headers` | 请求已写入，取得响应头之前失败 |
| `response_read` | 已有响应，读取正文时失败 |

没有对应事件就不猜阶段。累计握手、写请求、耗时等字段仍是整次检测的统计，不能据此推断某一条请求成功或失败。普通传输错误的 `FailurePhase` 使用具体阶段；取消仍是 `cancelled`，超时仍是 `timeout`，具体阶段另存在 Details。`timeout_origin` 区分 `checker_deadline` 和 `transport`。

原始 HTTP 状态、实际读取字节、底层取消/超时错误和脱敏规则保留，应用层照常将这些字段保存到历史；旧记录不重写。HTTP 403 验证页属于已连通但被网页验证阻挡，不因此宣称节点连接失败或服务业务可用。

Netflix 和 Antigravity 每个步骤开始时清除上一请求的顶层 HTTP 状态，避免后一步在响应头之前断连却带着前一步的 200。已完成片目的状态仍保存在逐片目 Details；当前响应头之后的正文错误继续保留当前 HTTP 状态和实际读取字节。Antigravity 保留原账号/目录/模型步骤名称，同时使用通用的请求失败阶段、超时来源与脱敏规则，不把底层传输超时一律称为总时限耗尽。

阶段错误包装同时保留 `net.Error` 的 Timeout/Temporary 行为，确保外层 `url.Error` 仍能识别网络超时，不仅能解包原错误。

多次采样的顶层 HTTP 状态和传输诊断来自同一个代表样本，`Details.http_status_scope` 标明来源：`first_sample`、`first_unconfirmed_sample`、`first_cancelled_sample` 或 `first_rate_limited_sample`。第一条未确认样本也可能是未执行；它的原因保留，仍不计作服务失败。`first_sample_http_status` 另存首样本实际取得的状态，未取得就省略。无响应的异常样本不会借用首样本的成功码；改为限流结论时清除此前样本的超时诊断。样本成功/失败/未知/取消/未执行/未启动计数及原有结论优先级保持。

验证覆盖复合请求后续 TLS 失败、代理建连失败、正文中断、超时/取消、HTTP/2 与 HTTP/1.1 回退；本地服务器验证也核对原节点拨号路径和实际连接次数。协议兼容改进不代表已证明某个历史超时的原因。

## 提前保留已确认的拦截

- Netflix 的任一片目响应带明确验证头时，关闭响应并结束本次片目链，不再等待错误正文。第一张片目已识别验证页时也不再请求第二张，避免后一次连接失败掩盖已有拦截。仅有标题或流量提示的页面仍是 `suspected_challenge`，不升级为明确拒绝；正常两片目判定保持。
- Antigravity 的账号、模型目录或生成步骤返回 HTTP 429 时，直接保留 `rate_limited` 与规范化的 Retry-After 提示，不再读取可能卡住的正文，也不发起后续步骤。失败阶段仍保留原步骤名称；没有扩大模型请求或添加重试。

以上分支用离线响应复现并回归，不代表在用户节点上新观察到了限流或验证拦截，也不改写已保存的旧失败。
