# IPPure 请求兼容修复（2026-10-19）

- 新规则 v7 优先使用 [官方公开 API](https://ippure.com/MyIP-Info-API) 取得当前节点的 IPv4、ASN、风险分，避免先被网页接口拒绝再回退。缺失、无效分数与 IPv6 不生成风险分。
- Cloudflare 网关原本未适配网站的正常密钥更新，且普通 Go TLS/HTTP 请求会受拒绝。采用现有依赖提供的 Chrome 133 TLS / HTTP2 组合，仅作用于 IPPure API 与 summary 两个固定主机；节点拨号、证书验证、取消、总时限保留。自定义代理或 TLS 策略不能被覆盖时保持原传输。
- 依据 IPPure 当前 `security.C1jHOmoV.js`，正常 API 密钥更新最多重放四次、总共五次；不重试 HTTP 403、429 或验证码挑战。整个检测仍共用原总时限；官方风险与Cloudflare子项并行，Cloudflare子项最多6秒，失败不会丢掉另一项已取得的结果。人机比在取得ASN后独立查询。
- 旧规则 v6 及更早版本维持原逻辑；旧历史不改写。旧记录未包含新字段时标记“旧记录待更新”。移除首页 IPv6“不支持评分”占位行。
- 系数反映 App 本次请求环境，不能声称等同于浏览器评分。ASN 人机比是全 ASN 的公共统计，不是节点流量占比；取不到数据时保留具体失败，不补0或借用其它ASN。
- 诊断记录仅本地保存。已在 SG04 诊断链取得 Cloudflare 99；截至源码修复时 ASN16509接口仍返回403，尚未取得人机比。最终原生App结果以本轮Handoff为准。
